# 价格来源登记册

这里记录**价格从哪来**：盒型购入价的出处、卡价的推导口径，以及本机能访问哪些查价站点。

与上一级 `sources/README.md` 的区别：那边的原始件是发行商发布的官方资料（配率、名单），
这里登记的是**市场信息**，天生带有时间与渠道属性，所以每一格都要求写清来源站点与记录日期。

## 一、结论先说

**本机能用的公开价格来源一共四类，其中只有一个是「卡价」：**

| 能拿到 | 站点 | 用途 |
| --- | --- | --- |
| 中文卡牌交易平台的挂牌价与成交价 | 卡淘 `www.cardhobby.com.cn` | 唯一的 RMB 卡价参照，成交价用来标定模型 |
| 发行商官方发售价（原价） | Checklist Insider 系列指南页 | 盒型购入价的出处，22 个盒型里 20 个靠它 |
| 汇率 | 中国银行外汇牌价 / ExchangeRate-API | 美元报价折算成 RMB |
| 只作对照 | 发行商与零售商官网 | 在售商品的价格能读到，下架商品整页不含价格 |

**逐张卡的真实价拿不到。** 卡淘的成交价虽然取得到，但对不到具体某一张卡上
（原因见第二节），所以它只用来**标定**模型；北美与欧洲的行情站要么挡在反爬墙后面，
要么要付费密钥 —— 完整的接口穿刺结果也记在第二节。

**盒价口径是发行商官方发售价**，俗称「原价卡盒」：官方公布的美元发售价折算成 RMB，
美元原值留在 `msrpUsd` 里备查；官方没公布过发售价的盒型退回公开零售报价，
用 `basis` 把两种口径标开，不再含糊地写成「参考价」。

## 二、实测记录（2026-10-01）

方法：`scripts/probe-price-sites.mjs`，Node 24 内置 fetch，12 秒超时，
Chrome 桌面版 UA，逐站记录状态码 / 响应字节数 / 最终地址。
命令：`node scripts/probe-price-sites.mjs [站点名片段]`。

### 可用

| 站点 | 结果 | 能拿到什么 |
| --- | --- | --- |
| `www.cardhobby.com.cn`（卡淘） | 200，约 115 KB | 列表页是服务端直出，每条含 `￥` 价格、运费、出价次数 |
| `www.checklistinsider.com` | 200，约 148 KB | 只有清单与配率 |
| `open.er-api.com` | 200 | `USD → CNY` 汇率 |
| `api.frankfurter.app` | 200，跳 `api.frankfurter.dev` | `USD → CNY` 汇率 |
| `www.boc.cn/sourcedb/whpj/` | 200，约 27.5 KB | 人民币口径的美元牌价 |

卡淘的列表页结构（2026-10-01 实测）：`<a href="/market/item/<id>">` 包住一条记录，
价格在 `<table class="card-info">` 里，形如
`<span style="font-size:16px;...">￥NNO</span>`，另有一行 `运费：￥18`。
注意它给的是**起拍价或一口价**，不是成交价。

**成交价能拿到（2026-10-01 补测）。** 检索结果其实由 JSON 接口返回，
不需要登录、不需要 Cookie，普通 Node fetch 就能调：

```
GET https://www.cardhobby.com.cn/NewCommodity/SearchCommodity
    ?userId=&pageIndex=N&pageSize=60
    &searchKey=<关键词，URL 编码>
    &searchJson=[{"Key":"Status","Value":-2}]        // -2 = 已售出，1 = 出售中
    &sort=EffectiveTimeStamp&sortType=DESC
```

需要浏览器 UA 和 `Referer: https://www.cardhobby.com.cn/market/search?keyword=<关键词>&searchtype=1`。
返回 `data.TotalCount` 与 `data.PagedMarketItemList[]`，单条记录的字段：

| 字段 | 含义 |
| --- | --- |
| `LowestPrice` | **成交价**（不是 `Price`，`Price` 恒为 `"1.00"`，是起拍价） |
| `PriceCount` | 出价次数 |
| `EffectiveDate` | 成交时间 |
| `NewPostageMoney` | 运费 |
| `Title` | 唯一的卡片身份线索，没有结构化的球员/系列/编号字段 |

三条必须记住的限制，否则数出来的价格是错的：

1. **分页有上限。** `pageIndex` 到第 8 页左右就到底（约 480 条），
   `TotalCount` 再大也翻不下去。要样本就得换关键词，不能加页码。
2. **`searchKey` 是子串匹配，不是分词。** `#8` 等价于 `8`，`Topps Basketball Luka Doncic`
   只剩 23 条而 `Topps Basketball` 有 29,469 条；带变音符号的 `Luka Dončić` 比 `Luka Doncic`
   少一半结果。所以**不能用系列名当关键词去横向比价**，词序和写法都会污染结果。
3. **绝大多数成交是 ￥1。** 那是单出价人的起拍价兜底，不是市场价。
   统计时只取 `PriceCount >= 2` 的样本，中位数就干净了。

即便有成交价，也**没法把它对到具体某一张卡上**：检索结果只有标题字符串，
而标题里塞满了「打包 / 多张 / 编号 / 瑕疵」这类噪声，同一个关键词的价格能从 ￥2 铺到 ￥336。
所以实时逐张查价仍然不成立，成交价只用来**标定**模型（见第三节）。

### 接口形态的穿刺（2026-10-01 补测）

上一节测的是**页面**。页面被挡不等于数据取不到，所以又单独把常见接口路径打了一遍 ——
结论是「有接口的都要密钥，不要密钥的都不是运动卡」。

| 结果 | 目标 | 说明 |
| --- | --- | --- |
| 400，响应体为 `Must provide an access token` | PriceCharting、SportsCardsPro | **接口真实存在**，付费拿到令牌就是唯一能持续取运动卡成交价的路径 |
| 401 | TCGplayer、JustTCG、CardTrader | 接口存在，需要凭据 |
| 410，跳到 `apiv2.cardmarket.com` | Cardmarket | 旧接口已迁移 |
| 429，`maximum admitted 100 per Day` | PSA 公开接口 | 存在，免密钥但每天 100 次 |
| 405（GET 不被允许） | eBay 换取 OAuth 令牌的端点 | 存在，要走客户端凭据 |
| 418 | eBay Finding 老接口 | 已退役 |
| 403 | Card Ladder、130point、COMC、DA Card World、StockX、eBay 搜索、Topps 官网的 `/products.json` 与 `/graphql` | 反爬墙 |
| 200 但 HTML 里没有价格字段 | midwestcards、sportscardmarket、fanaticscollect、goldin、alt.xyz | 都是前端渲染，接口路径藏在前端代码里挖不出来 |
| 200，免密钥可直接用 | `api.scryfall.com` | 万智牌，垂直不对（`api.pokemontcg.io` 也通，同样不对口） |

**一个反直觉的结论：Cloudflare 的 JS 挑战在真实浏览器里会自己过掉。**
Topps 官网和 DA Card World 用 `fetch` 一律落到「Just a moment...」，
但用浏览器打开时约 15 秒后挑战自动通过、页面正常加载。
所以上一级 `sources/README.md` 里「命令行与真实浏览器都落到拦截页」这句是错的，已改。
真正过不去的只有**要人工勾选**的挑战（Blowout Cards 的 Imperva/hCaptcha）。

**但官网过了墙也没用：下架商品整页不含价格。**
22 个盒型在 Topps 官方商店全部是售罄状态，实测商品页
（如 `2025-26-topps-finest-basketball-hobby-box`）有标题、有规格、有「Sold out」，
但整页 0 个价格元素、0 个 `application/ld+json`、内嵌数据里 0 个价格字段；
检索页能返回 1,306 条商品，同样一条价格都没有。
**发行商官方价只在发卖期存在，过期就不会留在自己的站上**，
所以官方价必须靠第三方指南页的归档（见第三节）。

## 三、所以价格怎么定

既然逐张联网查价不成立（在册卡种四千多个），价格走**登记 + 推导**两条腿：

| 价格 | 口径 | 存在哪 |
| --- | --- | --- |
| 盒型购入价 | 发行商官方发售价折算成 RMB（`basis: msrp`），逐条登记 | `src/data/prices/boxes.ts` |
| 卡价 | 档位基准价 × 限量系数 × 人物系数 × 系列系数 | `src/data/prices/card-values.ts` |

卡价模型是纯函数：只依赖卡本身的属性，不依赖时间、随机数或网络。
这样「复现这一盒」和「回填历史记录」都能算出同一个数。

### 盒价从哪来

每个条目带两个字段说清自己是哪种价：

- `basis: "msrp"` —— 发行商官方发售价，`msrpUsd` 里带美元原值，`cost = msrpUsd × USD_CNY`
- `basis: "retail"` —— 公开零售报价折算，只在官方没公布过发售价时使用

可信度 `confidence` 取值见 `src/data/prices/types.ts`：

- `verified` —— 在本机可访问的来源上逐字读到的价格
- `reference` —— 公开报价换算，出处能看到但没有官方口径可依
- `estimate` —— 同类盒型的合理估算，没有任何公开报价支撑

官方价取自 **Checklist Insider 的系列指南页**，它的盒型段落会写
「Topps presales appeared on <日期>, at $X per box. That increased to $Y on release day.」
这类句子 —— 这是本机唯一能逐字读到官方发售价的地方。
口径取**发售日价**，只有预售价可查时才用预售价，每条的 `note` 里标了出来。

### 系列档次系数：形状靠成交价，水位靠盒价

`src/data/prices/products.ts` 里的 `PRODUCT_VALUE_FACTORS` **不是从任何官方资料抄的**，
是两步标定出来的。

**第一步，形状取自卡淘成交价。** 用第二节那个接口按系列取已售出记录，
按「这个标题更像哪个系列」互斥分桶 —— 每一条只进最具体的那一个桶。
不分桶会重复计数：卖家的标题常常被塞进多个系列名，同一张卡会同时落进好几个系列，
把最宽泛的那个关键词（Topps Basketball）抬上去。分桶后丢掉噪声标题
（打包 / 多张 / 签名 / 实物 / 编号 / 卡品问题 / 代拍），只统计出价 ≥2 次的样本，
取中位数，再互相作比：

| 系列 | 入库 | 出价 ≥2 | 竞拍中位 | p25 | p50 | p75 | p90 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Topps Cactus Jack | 122 | 114 | ¥33.00 | 14.00 | 28.60 | 65.00 | 135.60 |
| Topps Cosmic Chrome | 122 | 63 | ¥14.00 | 1.00 | 2.00 | 16.00 | 98.09 |
| Topps Finest | 14 | 11 | ¥20.00 | 3.00 | 9.00 | 37.10 | 102.00 |
| Topps Signature Class | 90 | 72 | ¥10.00 | 3.00 | 7.10 | 24.00 | 95.00 |
| Topps NBA Hoops | 78 | 71 | ¥8.00 | 3.00 | 7.00 | 13.10 | 24.00 |
| Topps Chrome Update | 123 | 103 | ¥11.00 | 2.50 | 7.03 | 110.00 | 180.00 |
| Topps Basketball（旗舰） | 86 | 53 | ¥3.20 | 1.00 | 3.00 | 4.01 | 6.00 |
| Topps 3 | 1 | 1 | ¥93.00 | — | — | — | — |

结论和直觉相反：**旗舰 Topps Basketball 是最便宜的一档**，而 Cactus Jack、Finest
这些「单包贵、卡种少」的系列单张明显更贵。Topps 3 只有 1 条干净样本（该系列几乎
全是签名卡，全被噪声过滤掉了），没有可用信号，保持原值不动。

**第二步，水位由盒价钉住。** 上表的绝对值是国内二级市场的，盒价是北美零售的，
两者差 2~8 倍。直接照搬比值会让回本率冲到 120% 以上 —— 密封盒不可能长期回本超过 100%，
那说明水位错了，不是市场错了。所以把整组比值乘一个统一的系数，
让回本率中位数落回 50% 附近。这一步只动水位，不动系列之间的比例。

同一批数据还标过人物档位，但那次标定只用了**普卡市场**，后来被推翻了 ——
见下面「人物档位重新标定」一节。原来那组数字是 `SUPERSTAR_FACTOR` 4 → 6、

改完全体回本率中位数 50.4%，区间 19.6%~77.8%。区间比标定前宽（原来的做法是硬把每个
系列都塞进 45%~60%），这是有意的：现在的差异来自真实成交价，不是来自拟合盒价。

### 盒价换成官方发售价之后（2026-10-01）

上面那张「¥2880 → ¥2600」的修正表**已经被官方发售价取代**，留在这里只为记录
当时的判断依据。换成官方价后，22 个盒型里 18 个的登记价上升
（官方发售价普遍高于零售渠道的让步价），回本率中位数从 50.4% 落到 **28.7%**，
区间 14.8%~77.1%。

**没有把水位重新钉回 50%。** 卡价那一侧挂在卡淘成交价上，把系数整体乘 1.75
就能把中位数拉回 50%，但那等于宣布「一张卡的模型价比它在卡淘上的真实成交中位数
贵 75%」—— 和「卡价要接近真实价」直接冲突。所以这次只换盒价口径、不动模型：
**盒价照官方原价，卡价照成交标定**，两边各守各的锚，中间差多少就如实显示多少。

顺带得到一个更符合常识的结论：按官方原价开盒，越贵的盒型亏得越多
（`tcosmic26` 14.8%、`tcu26` Jumbo 16.4%、`tcu26` Hobby 22.4%），
反倒是 Value Blaster / Mega / Hanger 这类小规格盒型接近甚至超过 50%。
这比原来「所有系列都挤在 50% 上下」更像真的 —— 那本来就是拟合盒价的产物。

### 人物档位重新标定（2026-10-01）

**上一版的分档是在错误的市场上标的。** 它用「Topps NBA Hoops 非编号卡」按球员分组，
得到普通球员 ￥1~2、顶级档 ￥13.55，于是把顶级档定成 6 倍。那是**普卡市场**的比值。
而本站在册的贵卡几乎全是签名卡与低编平行卡，同一批球员在**签名卡市场**上的差距
要大一个数量级 —— 把普卡的倍数套到签名卡上，就得到「库珀弗拉格的 10 编签字只值
￥1,500」这种结果。

标定方法：同一个卡淘接口，`searchKey` 换成球员名（中文写法也要试，标题里
「维克托文班亚马」比「Victor Wembanyama」多得多），`searchJson` 仍取 `Status: -2`
（已售出），只统计出价 ≥2 次的记录，且要求球员名出现在标题**前 45 字**——
卖家会把十几个球员名塞进标题蹭流量，不限位置就会把别人的卡算进来（实测文班亚马的
桶里混进过 Jalen Pickett 的签字卡）。签字卡 / 非签名卡 / 低编（≤25 编）分三桶。

| 球员 | 签名卡中位 | 非签名卡中位 | 样本 n | 相对内姆哈德 |
| --- | --- | --- | --- | --- |
| Cooper Flagg | ¥9,034 | ¥62 | 5 | ×65 |

两个结论：

1. **签名卡市场的档位差距是 50~65 倍，不是 6 倍。** 库里 / 未分级球员在签名卡上
   相差 62 倍，在非签名卡上只相差 3~5 倍。
2. **人物溢价本身会被卡的档次放大。** 库里签名卡 ÷ 库里普卡 = 249 倍，
   内姆哈德签名卡 ÷ 内姆哈德普卡 = 13 倍。也就是说「这位球员的贵卡能贵多少」
   与「他的普卡贵多少」是两个量级的量，一个倍率不可能同时说对两头。

于是模型改成两层：`players.ts` 只管**档位**（超巨 30 / 巨星 7 / 球星 2.5 /
未分级 1），`card-values.ts` 的 `playerFactor` 再按卡的大类**打折**——
签名卡/实物卡/超短印吃满，普卡/平行卡/插入卡只吃 15%。这样超巨在签名卡上
是 ×30、在普卡上是 ×5.35，与实际观测的 ×62 / ×3~5 大体对上（签名卡那一头
取下沿，因为档位整体抬高会同时抬高每个盒型的平均售出额）。

顺带把库珀弗拉格从全明星档提到超巨档。他 2025 年是状元，实测签名卡中位 ￥9,034
（n=5），其中一张 Topps Definitive 10 编新秀签字成交 **￥24,250**。旧模型里他在
全明星档（×1.5），对同口径的卡（Topps Chrome Update、epic 档、10 编、新秀签字）
只给 **￥701**；现在给 **￥14,013**（`npm run prices:check` 会打印这个锚点），
与真实成交在同一量级。Definitive 本身不在在册系列里，没有对应的系列系数，
所以只能对量级，不能逐张对。

改动后回本率中位数从 28.7% 升到 **34.3%**，区间 15.0%~104.3%。没有把这个差额
回收掉：这是签名卡那一头原来被低估、现在补回来的结果，强行乘一个系数拉回 28.7%
等于又把星卡的价压下去。

实测值本身存了一份在 `src/data/prices/players.ts` 的 `TIER_EVIDENCE` 里（不参与
计算，只做存证），`npm run prices:check` 会核对它的档位标注跟分档表是否一致。

**已知偏差：** 档位只看得到「这次测的量级」，看不到走势。整个采样窗口只有 2026-09
一个月，数据里 2026-09-29 一天就占了很大比例，所以这一版描述的是「2026 年 9 月末
的价位」，不是趋势。要拿到趋势得按 `EffectiveDate` 分周统计，而卡淘这个接口
翻页上限大约 480 条，按月分桶之后每个球员每周只剩个位数样本 —— 这条路暂时走不通。

### 这次标定没有解决的

- **对不到单张卡。** 成交价只进了系列系数和人物档位这两个聚合量。
  想填 `card-values.ts` 里那张 `EXPLICIT` 表（按「系列 + 卡种 + 球员」精确命中），
  得先有能对上的数据源，目前没有 —— 卡淘的成交记录只有一串塞满关键词的标题，
  没有结构化的卡种/平行字段。比如「Topps Definitive Cooper Flagg RC 10编 ￥24,250」
  这条，Topps Definitive 根本不在本站的在册系列里，想登记也无处可挂。
  所以 `EXPLICIT` 目前仍然是空的，现在扛事的是分档表。
- **`tfinest26` 系列样本只有 14 条。** 11 条干净样本撑起 1.483 的系数，
  是所有系数里最脆的一格；拿到更多样本应该第一个复核它。
- **Topps 3 完全没有样本。** 该系列几乎只出签名卡，而签名卡全被噪声过滤器滤掉了，
  要标定它得单独设计一套「怎么从签名卡标题里认出系列」的规则。

## 四、复核命令

```bash
npm run prices:probe                     # 重新穿刺站点可用性（约 30 秒）
npm run prices:check                     # 盒价登记完整性 + 球员分级拼写 + 回本率
npm run prices:check -- thoops           # 只看某个系列
```

`prices:check` 的判定规则：盒价缺失、球员名拼错、人物档位比值跑出实测区间
**判定失败**；回本率看**全体中位数**（要求落在 25%~100%），单个盒型偏出只提醒不失败 ——
不同盒型的回收率本来就不一样，这是市场事实，不是数据错误。

## 五、历史记录里的金额怎么补

价格表上线前开的盒没有金额。补法不是估算，是**重放**：

```bash
npm run db:backfill                      # 本地库
npm run db:backfill -- --remote          # 线上库（先导出一份 breaks 留底）
```

能重放的原因写在 `scripts/backfill-break-values.ts` 的开头：
拆盒的随机数种子只由「盒型 key + 种子文本」拼接决定，而这两样每次都原样存进了 `breaks`，
所以每条老记录都能重开一遍，拿到当时的卡，再按当前价格表算出金额。
算出来的是「当时的卡按登记价现在值多少」，一条可以解释的数字，不是补一个平均数进去。

脚本只写变化的行，可以反复跑；盒型查不到（下架或改名）的记录跳过并打印，不猜价。
